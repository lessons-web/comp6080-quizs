## Week 1

### 本周主题

前端基础入门，建立 `HTML + CSS` 的底层认知。核心目标不是“记住几个标签和属性”，而是先理解浏览器如何解释页面结构、样式规则和布局关系。

### 1. HTML Fundamentals

#### 核心内容

- 理解 HTML 文档的基本结构：`<!doctype html>`、`<html>`、`<head>`、`<body>`
- 区分文档元信息与页面主体内容
- 理解常见标签的职责，例如标题、段落、列表、链接等
- 明白浏览器是按结构来解析页面，而不是“看到什么写什么”

#### 重点理解

- `<head>` 主要放元信息，不是给用户直接阅读的主体内容
- `<body>` 才是页面主要可见内容
- HTML 的首要作用是组织结构和表达语义，不只是“把文字放上去”

#### 常见误区

- 认为 `<head>` 里的内容也属于页面正文
- 把 HTML 理解成纯展示语言，而忽略了结构和语义
- 页面里大量使用没有意义的标签，导致结构混乱

#### quiz 常见考法

- 判断某段代码中哪一部分属于页面主体
- 解释 `<head>` 和 `<body>` 的职责区别
- 识别 HTML 基本文档是否完整

### 2. HTML 语义化与页面结构

#### 核心内容

- 理解语义化标签的意义，例如 `header`、`nav`、`main`、`section`、`article`、`footer`
- 知道语义化标签为什么比单纯使用 `div` 更好
- 明白结构清晰会影响可读性、可维护性和可访问性

#### 重点理解

- 语义化不是“写得高级”，而是让结构表达更准确
- 语义化标签有助于浏览器、开发者和辅助技术理解页面
- 同样的视觉效果，不同的结构写法会产生不同的专业性

#### 常见误区

- 认为语义化只是一种“代码风格”
- 无论什么场景都只用 `div`
- 标题层级混乱，例如直接从 `h1` 跳到 `h4`

#### quiz 常见考法

- 判断哪种结构更语义化
- 给出页面场景，让学生选择更合适的标签
- 比较 `div` 和语义化标签在表达意义上的差异

### 3. 图片、路径与可访问性

#### 核心内容

- 理解相对路径与绝对路径
- 学会在 HTML 中插入图片
- 理解 `alt` 文本的作用
- 明白图片不仅是“能显示出来”，还要考虑可访问性和语义

#### 重点理解

- 相对路径依赖当前文件位置
- 以 `/` 开头的路径通常从站点根目录开始解析
- `alt` 应该描述图片的用途，而不是机械重复“这是一张图片”
- 当图片无法显示时，`alt` 也是重要的信息补充

#### 常见误区

- 分不清 `images/logo.png` 和 `/images/logo.png`
- `alt` 写成无意义文本，例如 `image`
- 只关心图片能不能显示，不关心信息表达

#### quiz 常见考法

- 判断某段路径是否能正确找到资源
- 分析哪种 `alt` 文本写法更合理
- 判断图片标签缺少什么信息

### 4. SVG 图片基础

#### 核心内容

- 认识 SVG 是矢量图
- 理解 SVG 与 PNG/JPG 这类位图的差异
- 知道 SVG 适合图标、logo、简单图形等场景

#### 重点理解

- SVG 放大通常不会失真
- 位图依赖像素，放大会模糊
- 选择图片格式本身也是前端判断能力的一部分

#### 常见误区

- 认为 SVG 只是“另一种图片扩展名”
- 不理解矢量图与位图在网页中的实际区别
- 在不合适的场景下盲目使用某一种格式

#### quiz 常见考法

- 判断某个场景更适合 SVG 还是 PNG/JPG
- 解释 SVG 为什么适合图标和 logo

### 5. 更多 HTML 标签与代码展示标签

#### 核心内容

- 补充常见内容类和结构类标签
- 学习 `<code>` 与 `<pre>` 的作用
- 理解“表示代码”与“保留格式”是两个相关但不同的概念

#### 重点理解

- `<code>` 用来标识内容是代码
- `<pre>` 用来保留空格、换行和原始格式
- 两者经常一起使用，但职责不同

#### 常见误区

- 认为 `<pre>` 就等于“代码标签”
- 不知道为什么代码片段在浏览器里格式会乱
- 只写 `<code>` 而不理解格式保留问题

#### quiz 常见考法

- 问 `<code>` 和 `<pre>` 的区别
- 判断某种代码显示需求该使用哪些标签

### 6. CSS Rules

#### 核心内容

- 理解 CSS 规则由选择器和声明组成
- 学习元素选择器、类选择器、id 选择器
- 理解层叠、优先级、继承等概念

#### 重点理解

- 样式生效的前提是选择器真正匹配到元素
- 多条规则同时命中时，要看优先级和出现顺序
- 不是“写了 CSS 就一定生效”，而是要理解为什么生效或不生效

#### 常见误区

- 把 `class` 和 `id` 混用
- 不知道选择器根本没匹配到目标元素
- 一看到样式不生效就盲目加更高优先级

#### quiz 常见考法

- 判断某条规则会不会命中某个元素
- 比较哪条样式最终生效
- 分析 class selector 与 id selector 的区别

### 7. CSS Formatting

#### 核心内容

- 学习文本样式、颜色、字体、对齐方式
- 理解 `margin`、`padding`、`border`
- 学习显示方式，例如块级与行内元素

#### 重点理解

- `padding` 是元素内部空间
- `margin` 是元素外部空间
- `border` 是盒子边界的一部分
- 样式修改不仅影响视觉，也影响盒模型占用空间

#### 常见误区

- 分不清 `margin` 和 `padding`
- 认为设置了宽度，元素实际占用宽度就固定不变
- 忽略边框和内边距对总尺寸的影响

#### quiz 常见考法

- 判断某个元素最终会占多少空间
- 分析为什么两个元素之间间距不符合预期
- 解释某个布局问题该改 `margin` 还是 `padding`

### 8. CSS Layouts

#### 核心内容

- 理解网页布局的基本思路
- 学会从“单个元素样式”上升到“多个元素如何组织”
- 知道页面结构稳定比局部对齐更重要

#### 重点理解

- 布局问题本质上是父子关系和元素排列关系问题
- 页面结构不清晰时，后续样式会越来越难维护
- 做布局时要先看容器，再看子元素

#### 常见误区

- 只改子元素，不看父容器
- 用大量固定数值硬挤位置
- 能显示出来就算完成，不考虑结构稳定性

#### quiz 常见考法

- 问“为什么这个布局不稳定”
- 给出页面结构，判断应优先修改父元素还是子元素

### 9. CSS Flexbox

#### 核心内容

- 学习 `display: flex`
- 理解主轴和交叉轴
- 学习 `justify-content`、`align-items`、`gap`
- 明白 Flexbox 是一维布局工具

#### 重点理解

- Flexbox 一般设置在父容器上，由父容器控制子元素排列
- `justify-content` 处理主轴方向分布
- `align-items` 处理交叉轴方向对齐
- 先理解轴方向，再谈属性效果

#### 常见误区

- 把 Flexbox 写到子元素上，期待它控制兄弟元素排列
- 不理解主轴和交叉轴，导致属性乱用
- 用固定 `margin-left` 模拟居中或间距分布

#### quiz 常见考法

- 问某个布局需求该用哪个 Flexbox 属性
- 判断为何子元素没有按预期排列
- 解释 `justify-content` 和 `align-items` 的区别

### 10. CSS Z-index

#### 核心内容

- 理解元素层叠顺序
- 认识定位与层叠上下文的关系
- 理解为什么 `z-index: 9999` 也不一定“压在最上面”

#### 重点理解

- `z-index` 生效往往与定位有关
- 元素可能被限制在不同的 stacking context 中
- 层叠问题不能只看一个元素的数值，还要看祖先关系

#### 常见误区

- 遇到覆盖问题就无限增大 `z-index`
- 忽略定位和父容器上下文
- 不理解“同一上下文里比较”和“不同上下文里比较”的区别

#### quiz 常见考法

- 判断 `z-index` 为什么不生效
- 分析哪一个元素最终显示在上层
- 判断“只要 z-index 足够大就一定在最上面”这句话对不对

### 11. CSS Preprocessors

#### 核心内容

- 认识 CSS 预处理器的作用
- 理解变量、嵌套、复用等能力
- 明白预处理器的价值在于样式工程化

#### 重点理解

- 预处理器是帮助开发的工具，不是浏览器直接理解的最终语言
- 它的意义在于减少重复、提升可维护性
- 学习它的重点是理解为什么样式需要工程化

#### 常见误区

- 以为预处理器只是“写法不一样”
- 只会机械写嵌套，不知道什么时候应该拆分结构

#### quiz 常见考法

- 问预处理器存在的意义
- 比较普通 CSS 和预处理器在可维护性上的差异

## Week 2

### 本周主题

从纯 `HTML/CSS` 过渡到更接近真实开发的前端基础，包括移动端适配、开发者工具、JavaScript 基础语法，以及 `Node / NPM` 生态。

### 1. Mobile CSS

#### 核心内容

- 理解移动端优先和响应式思路
- 认识不同屏幕尺寸下页面布局会发生变化
- 学会从“设备适配”角度看待样式设计

#### 重点理解

- 同一个页面不一定在所有设备上都用同一套布局表现
- 移动端页面更强调内容优先、结构清晰和可点击性
- 响应式不是“把桌面版缩小”，而是重新思考布局

#### 常见误区

- 只在桌面浏览器上看效果
- 用固定宽度写页面，忽略不同设备
- 把移动端适配理解成纯视觉缩放

#### quiz 常见考法

- 问移动端样式设计关注的重点是什么
- 比较固定布局与响应式布局的差异

### 2. CSS Frameworks

#### 核心内容

- 认识 CSS 框架的作用
- 理解为什么很多项目不会从零开始写所有样式
- 知道框架和自定义样式各自的适用场景

#### 重点理解

- 框架的价值在于提升开发效率和一致性
- 使用框架不代表不需要理解 CSS 原理
- 不理解原理时，框架会变成“只会拼类名”

#### 常见误区

- 以为用了框架就不需要学习 CSS
- 遇到样式问题只会试错，不知道底层原因
- 盲目追求框架，而忽略项目需求

#### quiz 常见考法

- 问为什么项目中会使用 CSS Framework
- 比较框架样式与手写样式的优缺点

### 3. Dev Tools

#### 核心内容

- 学习浏览器开发者工具的基本用法
- 会查看元素结构、样式来源、盒模型、网络请求和报错
- 知道如何用工具定位前端问题

#### 重点理解

- DevTools 是前端调试的核心工具
- 页面问题不能只靠“猜”，要靠工具验证
- 理解样式来源和覆盖链路是排错关键

#### 常见误区

- 页面出错只看代码，不看浏览器控制台
- 不会用 Elements 面板检查样式覆盖
- 对调试工具停留在“会打开，但不会分析”

#### quiz 常见考法

- 问开发者工具可以帮助检查什么
- 给一个前端问题场景，问应该用哪个面板定位

### 4. JavaScript 基础语法

#### 核心内容

- 变量、数据类型、条件、循环、函数、对象
- 学习基本表达式和流程控制
- 建立“JavaScript 是让页面产生行为的语言”这一认知

#### 重点理解

- JavaScript 不只是“写点小脚本”，而是整个前端交互的核心语言
- 函数是组织逻辑的核心单位
- 条件和循环控制程序执行路径

#### 常见误区

- 会背语法，但不会解释运行结果
- 对变量和作用域理解模糊
- 只看表面输出，不理解逻辑过程

#### quiz 常见考法

- 预测一段 JavaScript 代码输出
- 分析条件和循环执行结果
- 问函数在程序中的作用

### 5. JavaScript Ecosystem

#### 核心内容

- 理解 JavaScript 已经不仅仅是浏览器脚本
- 认识运行时、库、框架、打包工具、包管理等概念
- 建立“生态”视角，而不是只看语法

#### 重点理解

- JavaScript 是语言，生态是围绕它形成的开发体系
- 学前端不能只学语法，还要理解工具链
- 生态越大，越需要知道每个工具在做什么

#### 常见误区

- 把所有工具都混成“JavaScript 本身”
- 不知道 Node、npm、框架、库之间的关系

#### quiz 常见考法

- 问 JavaScript 生态包含哪些部分
- 区分语言本体和开发工具的角色

### 6. Node Package Manager

#### 核心内容

- 理解 `npm` 的作用
- 学习依赖安装、`package.json`、脚本命令等基础
- 理解前端项目为什么要有依赖管理

#### 重点理解

- `npm` 不只是安装包，它也是项目依赖和脚本管理工具
- `package.json` 是项目配置与依赖信息的核心文件
- 现代前端开发离不开包管理

#### 常见误区

- 只会复制安装命令，不知道装了什么
- 不理解 dependencies 与项目运行的关系
- 不知道 scripts 的作用

#### quiz 常见考法

- 问 `package.json` 的作用
- 问 `npm` 在前端项目中的价值

### 7. JavaScript Advanced Functions

#### 核心内容

- 理解函数是一等公民
- 学习回调函数、高阶函数等概念
- 认识更灵活的函数使用方式

#### 重点理解

- 函数可以被传递、返回和复用
- 高阶函数是现代 JavaScript 很重要的思维方式
- 写法变复杂时，重点是理解数据和控制流怎么走

#### 常见误区

- 只会调用函数，不理解函数也可以作为值
- 一看到函数嵌套就完全失去结构感

#### quiz 常见考法

- 问什么是回调函数
- 问为什么函数可以作为参数传入

### 8. NPM Advanced

#### 核心内容

- 学习更进一步的依赖管理与脚本使用
- 理解版本、脚本、项目工作流之间的关系
- 认识前端项目不是“单文件开发”，而是工程化协作

#### 重点理解

- 工程化开发强调统一命令、统一依赖和统一环境
- 版本控制和脚本命令都是项目稳定性的一部分

#### 常见误区

- 只把 npm 当作“安装器”
- 不重视项目脚本和环境一致性

#### quiz 常见考法

- 问 npm scripts 为什么有价值
- 问依赖版本管理为什么重要

### 9. JavaScript 与 NodeJS Demo

#### 核心内容

- 通过示例把 JavaScript 语法、Node 运行环境与 npm 串起来
- 帮助学生把零散知识点转成项目认知

#### 重点理解

- 前端知识不是孤立的标签，而是一套连贯工作流
- 真正的学习目标是从“知道概念”走向“知道如何运行”

#### 常见误区

- 学了语法却不知道如何放进项目里
- 学了 npm 却不知道为什么要执行脚本

#### quiz 常见考法

- 给出一个项目场景，问 JavaScript、Node、npm 分别扮演什么角色

### Week 2 复习重点

- 响应式与移动端思维
- CSS Framework 的价值
- DevTools 的调试作用
- JavaScript 基础语法
- JavaScript 生态
- `npm` 与 `package.json`
- 函数进阶
- 工程化开发基础

## Week 3

### 本周主题

把 JavaScript 放回浏览器环境中，开始理解网页如何通过 DOM、事件、表单和本地存储变成“可以交互的页面”。

### 1. 浏览器端 JavaScript Intro

#### 核心内容

- 理解浏览器中的 JavaScript 与 NodeJS 环境的区别
- 认识脚本如何在网页中被引入和执行
- 理解“页面行为”是如何由浏览器端脚本驱动的

#### 重点理解

- JavaScript 在不同运行环境中能力不同
- 浏览器环境提供了 DOM、事件、表单等 API
- 语法相同，不代表运行环境完全一样

#### 常见误区

- 把浏览器 JavaScript 和 NodeJS 视为完全一样
- 不理解环境差异带来的 API 差异

#### quiz 常见考法

- 问浏览器中的 JavaScript 和 NodeJS 的区别
- 判断某段代码更适合在哪个环境运行

### 2. Browser DOM

#### 核心内容

- 理解 DOM 是文档对象模型
- 学习如何读取、修改、创建页面元素
- 明白页面不是“死的 HTML”，而是可被脚本操作的结构树

#### 重点理解

- DOM 是 JavaScript 与页面沟通的桥梁
- 通过 DOM 可以查找元素、改文本、改属性、改结构
- 对 DOM 的理解是后续交互开发的核心

#### 常见误区

- 只会背 API，不理解 DOM 的整体概念
- 改页面时只关注结果，不知道操作的是哪一层结构

#### quiz 常见考法

- 问 DOM 是什么
- 给一段场景，问应如何通过 JavaScript 改页面内容

### 3. Browser Events

#### 核心内容

- 学习事件机制
- 理解点击、输入、提交等交互如何被监听和处理
- 认识“用户行为触发代码执行”的基本流程

#### 重点理解

- 事件是交互的入口
- 前端不是一直在主动执行，而是大量依赖事件触发
- 事件监听意味着“当某件事发生时，执行指定逻辑”

#### 常见误区

- 不理解事件和函数调用的关系
- 混淆“注册事件”与“立即执行函数”

#### quiz 常见考法

- 问事件监听的意义
- 判断某段代码是否正确绑定了事件

### 4. Browser Forms

#### 核心内容

- 理解表单的结构与提交流程
- 学习输入、提交、校验和用户交互关系
- 明白表单是前端最重要的交互载体之一

#### 重点理解

- 表单不仅是输入框，还包含提交行为和数据组织
- 表单处理通常涉及 DOM、事件和数据校验
- 用户输入是动态数据的重要来源

#### 常见误区

### 5. Browser LocalStorage

#### 核心内容

- 认识浏览器本地存储
- 理解页面刷新后如何保留简单数据
- 学习前端如何在本地保存用户状态

#### 重点理解

- LocalStorage 适合保存简单、轻量、键值形式的数据
- 它是浏览器端存储，不是服务端数据库
- 刷新页面后数据仍可保留，是它的重要特点

#### 常见误区

- 把 LocalStorage 和后端持久化混为一谈
- 不了解它适合存什么、不适合存什么

#### quiz 常见考法

### 6. JavaScript Closures

- 理解函数作用域与状态保留

#### 重点理解

- 闭包的核心是“函数与其词法环境的结合”
- 闭包让函数可以保存内部状态
- 在前端交互、封装逻辑和状态管理中都很常见

#### 常见误区

- 把闭包当成纯理论定义，不知道实际意义
- 只会背概念，不会解释为什么状态能被保留下来

#### quiz 常见考法

### 7. JavaScript Web Demo

#### 常见误区

## Week 4

### 本周主题

进入前端异步与网络通信，开始理解浏览器如何与服务器交换数据，以及 JavaScript 如何处理异步流程。

### 1. Data Interchange

#### 核心内容

- 理解前后端为什么需要交换数据
- 认识结构化数据的组织方式
- 建立“前端显示的数据通常来自外部输入或服务器”的视角

#### 重点理解

- 数据交换是前后端协作的基础
- 页面内容不总是写死在 HTML 中，很多数据来自请求返回
- 数据结构的清晰程度会影响前端处理难度

#### 常见误区

- 只把网页看成静态页面
- 不理解为什么前端需要解析和组织数据

#### quiz 常见考法

- 问前后端数据交换为什么重要
- 问结构化数据在 Web 中的意义

### 2. AJAX Intro

#### 核心内容

- 建立异步请求的整体认知
- 理解为什么页面不需要整页刷新也能更新局部内容
- 明白 AJAX 的核心是“异步地向服务器请求数据”

#### 重点理解

- AJAX 不是某一个单独 API，而是一种异步更新页面的思路
- 它让页面交互更流畅
- 用户操作和服务器响应之间不一定是同步阻塞关系

#### 常见误区

- 把 AJAX 误解成某一段固定语法
- 不理解“异步更新页面”的本质

#### quiz 常见考法

- 问 AJAX 的作用
- 问为什么 AJAX 可以避免整页刷新

### 3. AJAX XHR

#### 核心内容

- 学习 `XMLHttpRequest` 的基本工作方式
- 理解早期浏览器如何发起异步请求
- 认识它在现代开发中的历史意义

#### 重点理解

- XHR 是较早的浏览器请求方式
- 它能帮助理解异步请求的基本机制
- 即使现代开发更常用 `fetch`，理解 XHR 仍有助于建立基础

#### 常见误区

- 只记名字，不知道它解决什么问题
- 不理解它与 `fetch` 的时代关系

#### quiz 常见考法

- 问 XHR 是做什么的
- 比较 XHR 和现代请求方式的差别

### 4. AJAX Fetch

#### 核心内容

- 学习 `fetch` API 的基础使用
- 理解现代浏览器如何发起网络请求
- 明白请求和响应是前端处理远程数据的关键过程

#### 重点理解

- `fetch` 是现代前端常用的请求方式
- 发请求只是第一步，处理响应同样重要
- 需要理解 Promise 与异步处理的关系

#### 常见误区

- 只会写 `fetch`，不会解释返回结果怎么处理
- 不理解异步返回为什么不能像同步赋值那样直接拿结果

#### quiz 常见考法

- 问 `fetch` 的作用
- 问为什么请求结果通常需要异步处理

### 5. JavaScript Async Callbacks

#### 核心内容

- 理解回调在异步编程中的作用
- 认识异步流程为什么会嵌套和变复杂
- 学习回调是早期组织异步逻辑的常见方式

#### 重点理解

- 回调能把“未来发生的事”交给函数处理
- 问题不在于回调本身，而在于复杂流程会降低可读性
- 这是理解后续 Promise 和 `async/await` 的基础

#### 常见误区

- 只知道“回调地狱”这个词，不知道本质问题是什么
- 不理解为什么异步逻辑不能按同步顺序直接写

#### quiz 常见考法

- 问回调在异步编程中有什么作用
- 分析回调嵌套为何会降低代码可读性

### 6. JavaScript Async / Await

#### 核心内容

- 学习 `async/await` 语法
- 理解它如何让异步代码更接近同步阅读体验
- 知道它本质上仍然是在处理异步流程

#### 重点理解

- `async/await` 提高了可读性，但没有把异步变成真正同步
- 它是建立在 Promise 之上的更现代写法
- 学习重点是“流程表达更清晰”，不是只会背语法

#### 常见误区

- 误以为 `await` 会让所有逻辑都同步执行
- 会写语法，但说不清背后的异步含义

#### quiz 常见考法

- 问为什么 `async/await` 更易读
- 问它和回调相比改进了什么

### 7. HTTP Server

#### 核心内容

- 理解服务器在前后端通信中的角色
- 认识请求、响应、接口这些基础概念
- 建立前端不是孤立存在，而是需要与服务端协作的视角

#### 重点理解

- 前端向服务器发请求，服务器返回响应
- 接口是前后端协作的连接点
- 学习异步请求时，必须同时理解服务端的存在

#### 常见误区

- 把服务器理解成“很远的黑盒”
- 不理解请求和响应的基本关系

#### quiz 常见考法

- 问 HTTP Server 在 Web 中扮演什么角色
- 问客户端和服务端的基本交互流程

### Week 4 复习重点

- 数据交换
- AJAX 基本思路
- XHR
- Fetch
- 异步回调
- `async/await`
- HTTP Server 与前后端通信
