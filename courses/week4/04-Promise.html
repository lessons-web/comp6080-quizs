Promise 是一个未来值的代理

它代表一个「现在还没有、将来才会有」的值。关于 Promise 需要记住的事情很多， 但有且只有一件是必须记住的：状态一旦定型就不可再变。 这一节先把状态说透，再说链式和四个编排工具。

必考 pending / fulfilled / rejected then / catch / finally all / allSettled / race / any unhandledrejection
1.1

为什么需要 Promisefrom callbacks to promises

上一节 fetch 已经透露了答案：网络请求的结果不是立刻就有的。 如果用回调来接收这个「未来才出现的结果」，那么每一步后续操作都只能塞进上一步的回调里。

✗ 回调嵌套：层层往里缩，错误处理散落各处
// 拿到用户 → 再拿订单 → 再拿订单详情，一层套一层
getUser(1, function (err, user) {
  if (err) return handle(err);
  getOrders(user.id, function (err, orders) {
    if (err) return handle(err);
    getDetail(orders[0].id, function (err, detail) {
      if (err) return handle(err);
      render(detail);
    });
  });
});
✓ Promise 链：未来值先传递，处理稍后再挂上去
getUser(1)
  .then(user => getOrders(user.id))
  .then(orders => getDetail(orders[0].id))
  .then(render)
  .catch(handle);   // 任意一步出错都汇到这里
一句话
Promise 把「未来值」变成一个可以先传递、后挂载处理器的对象。 于是链式、分支、统一的错误处理才成为可能 —— 回调做不到的事情，本质上是因为 那个值在回调写法里根本没有名字，只能待在括号里。
1.2

★ 四种状态，一个不可逆的性质the state machine

一个 Promise 从出生到结束，只可能在下面这四种状态里。前三个是互斥的「取值」， 第四个 settled 是后两者的统称。

state 01

pending · 尚未定型

操作还在进行中，结果未知。这是 Promise 刚创建时的唯一状态。

state 02

fulfilled · 成功

操作成功完成，并带有一个「兑现值」。之后所有 .then 都会拿到这个值。

state 03

rejected · 失败

操作失败结束，并带有一个「拒绝原因」（通常是一个 Error）。

state 04 · 统称

settled · 已定型

fulfilled 与 rejected 的合称，意思是「结果已经确定，不再变了」。

不可逆
状态只能从 pending 单向变到 fulfilled 或 rejected，变过去之后就不能再变。 这是「链式能够成立」的前提：如果状态还能反复横跳，后续的 .then 就永远无法确定该走成功分支还是失败分支。也正因为这样，重复调用 resolve / reject 会被忽略—— 只有第一次调用有效，后面的调用连一个错误都不会报，只是安静地失效。
为什么重要
右侧演示台可以亲手验证这件事：先让它成功定型，再连点几次 resolve，你会看到状态纹丝不动。
1.3

构造器与三个方法then / catch / finally

new Promise(executor) 里的函数会立刻同步执行； 它拿到两个参数，调用 resolve(v) 表示兑现，调用 reject(e) 表示拒绝。

javascript demo/promise-basics.js 
// ① 构造器：里面的代码立刻同步执行
const p = new Promise(function (resolve, reject) {
  console.log('构造器里的代码立刻执行，这时状态是 pending');
  setTimeout(function () {
    resolve('来自服务器的数据');   // 第一次调用生效 → pending 变 fulfilled
  }, 1000);
});

// ② then / catch / finally 是「先挂上去，等定型之后再被调用」
p.then(function (value) {
  console.log('then 成功分支：', value);
  return value.length;            // 返回值会被自动包成一个新的 Promise
}).catch(function (err) {
  console.log('catch 失败分支：', err.message);
}).finally(function () {
  console.log('finally：无论成功还是失败都会跑，用来做收尾');
});

// 成功路径：then  → finally
// 失败路径：      catch → finally   ← finally 在两条路径上都会执行
  • .then(onFulfilled, onRejected)：处理成功，并且返回一个新的 Promise，所以能一路链下去。第二个参数一般不用，交给 .catch。
  • .catch(fn)：捕获链上最近一次的拒绝，本质是 .then(null, fn) 的语法糖。
  • .finally(fn)：无论成功失败都执行，用来关 loading、断开连接；它不接收值，也通常不改结果。
顺序
记住这三个方法在两条路径上的位置：成功走 then → finally，失败走 catch → finally。 finally 总是最后一道，所以清理逻辑放它里面最稳。
1.4

链式与分支chaining & branching

每个 .then 都会返回一个新的 Promise（课件里的比喻是像俄罗斯套娃一样层层包裹）， 所以可以一直往下接。注意：包裹顺序是嵌套的，但执行顺序是「最内层先跑」的栈式顺序。

javascript demo/promise-chain.js 
// 链式：后一个 then 收到的是前一个 then 的返回值
Promise.resolve(1)
  .then(function (v) {
    console.log('第 1 层收到', v);   // 1
    return v + 1;                    // 返回普通值，会被自动包成 Promise
  })
  .then(function (v) {
    console.log('第 2 层收到', v);   // 2
    return v * 10;
  })
  .then(function (v) {
    console.log('第 3 层收到', v);   // 20
  });

// 分支：同一个 Promise 上挂多个 then，它们都会收到同一个值
const shared = Promise.resolve('同一个值');
shared.then(v => console.log('分支 A', v));
shared.then(v => console.log('分支 B', v));
shared.then(v => console.log('分支 C', v));
// 父 Promise 定型后，三个分支按注册顺序被依次调用

// ✗ 常见错误：忘了 return，下一个 then 拿到的是 undefined
Promise.resolve(1)
  .then(function (v) { v + 1; })            // 忘了 return
  .then(function (v) { console.log(v); });  // 打印 undefined
常见坑
.then 里忘了 return， 下一个 .then 收到的就是 undefined， 链看起来没断，但值是空的。想往下传东西，就一定写 return。
1.5

错误处理与全局兜底errors & unhandledrejection

Promise 在错误处理上有个很省心的约定：里面抛出的任何异常都会自动变成 rejection， 你不需要手动 reject。显式拒绝才需要自己调 reject()。

javascript demo/promise-errors.js 
// ① 抛出的异常自动变成 rejection
new Promise(function (resolve, reject) {
  throw new Error('同步抛出的错误');
}).catch(function (err) {
  console.log('被 catch 接住：', err.message);
});

// ② catch 里可以继续抛，把错误交给下一个 catch
Promise.reject(new Error('第一次失败'))
  .catch(function (err) {
    console.log('第 1 个 catch 处理：', err.message);
    throw new Error('换了个错误继续抛');
  })
  .catch(function (err) {
    console.log('第 2 个 catch 兜底：', err.message);
  });

// ③ catch 之后还能继续 then：失败后走备选方案再往下走
fetchData()
  .catch(function () { return '默认数据'; })   // 失败就退回默认值
  .then(function (data) {
    console.log('真数据也好、兜底数据也好，流程都能继续', data);
  });

// ④ catch 接不住「异步回调里稍后抛出」的错误
//    课件原话：Promises always asynchronous，当前函数上下文总是先结束
new Promise(function (resolve) {
  setTimeout(function () {
    throw new Error('这个错误 catch 抓不到');
  }, 0);
}).catch(function (err) {
  console.log('这一行永远不会执行');
});

// ⑤ 所以要在全局挂一个兜底，专门收「没被任何 catch 处理」的拒绝
window.addEventListener('unhandledrejection', function (event) {
  console.warn('有 Promise 被拒绝且没人处理：', event.reason);
  event.preventDefault();   // 阻止浏览器默认的控制台报错
});
★ 最重要的一条
第 ④ 点的时机问题是这一节最容易忽略的地方：.catch 只能捕获 同步执行阶段抛出的异常。如果异常是在一个稍后才运行的异步回调里抛出的， 那时 Promise 的执行上下文早就结束了，.catch 无从下手。 所以真实项目里几乎一定会挂一个 unhandledrejection 监听， 它才是「漏网的拒绝」的最后一层防线。
1.6

Promise 编排六件套combinators

单个 Promise 只能表达一件事，多个 Promise 一起用时靠这六个静态方法决定「怎么汇总」。

方法 一句话定义 什么时候用
Promise.all(list) 全部成功才成功，有一个失败就立刻整体失败 这些数据我全都要，缺一个就不渲染
Promise.allSettled(list) 等全部有结果（不管成功失败）才成功，返回每项 {status, value|reason} 失败几个也没关系，能渲染多少就渲染多少
Promise.race(list) 最先定型的那一个决定结果，成功失败都算 给请求加超时：拿它和一段 setTimeout 比快
Promise.any(list) 最先成功的那一个决定结果，全部失败才失败（抛 AggregateError） 多个镜像源，谁先回来用谁
Promise.resolve(v) 立刻得到一个已兑现的 Promise 把普通值包成 Promise，统一接口
Promise.reject(e) 立刻得到一个已拒绝的 Promise 造一个失败态，方便写测试或做分支
一句话
all 与 allSettled 的差别， 就是「一个都不能少」和「有几个算几个」的差别。 右边演示台点这两个按钮各跑一次，结论里的「成功 / 失败」会立刻分出胜负。
1.7

了解即可：thenablepromise-like

任何带 then() 方法的对象都算 thenable（也叫 promise-like）， 可以直接参与链式调用。.then() 与 await 在处理返回值时，都会把这种对象当成 Promise 来看待。

javascript demo/thenable.js 
// 手写一个 thenable：只要有一个 then 方法，就能「混进」链式调用
const thenable = {
  then: function (onFulfilled) {
    setTimeout(function () { onFulfilled('我是 thenable 给的值'); }, 200);
  }
};

// 把它当成返回值交给链，后面的 then 照常拿到值
Promise.resolve()
  .then(function () { return thenable; })
  .then(function (value) {
    console.log('收到：', value);   // "我是 thenable 给的值"
  });
程度
考官一般只要求知道这个名字和「有 then 就算数」这一条，不必手写实现。
1.8

这一节要带走的三句话takeaways

01

pending 只能变成 fulfilled 或 rejected，且不可逆

定型之后再调 resolve / reject 会被静默忽略。这是链式能成立的前提。

02

每个 then 都返回一个新的 Promise

所以能一路链下去；同一个 Promise 挂多个 then 就是分支，按注册顺序执行。

03

all 是「一个都不能少」，allSettled 是「有几个算几个」

再加上 race 抢最先定型、any 抢最先成功，四个工具决定多任务怎么汇总。
