很多人把 **UI** 和 **UX** 当成同一个东西，甚至把二者都简化为「界面好看」。实际上它们关注的是产品设计里两条不同的线：一条管**用起来合不合理**，一条管**看起来清不清楚**。一个能用但丑的产品（UX 好、UI 差）和一个好看但难用的产品（UI 好、UX 差）都真实存在。

## 1. UX：User Experience（用户体验）

UX 关心的是**用户完成目标的整个体验过程**，它的三个关键词是：

| 关注点 | 含义 | 典型工作 |
|---|---|---|
| 可用性 usability | 用户能否顺利、低挫败地完成目标 | 走查任务流程，找出卡点 |
| 逻辑性 | 信息与步骤的先后是否讲得通 | 梳理信息架构、流程图 |
| 用户研究 user research | 用真实反馈代替拍脑袋 | 用户访谈（interview）、可用性测试（usability testing） |

> ⚠️ 常见误区：**UX 不是「用户体验很好」这种模糊评价**。它是一个学科方向，核心落到**可用性与逻辑性**上，可以用访谈、测试等方法来度量和改进。

UX 的问题长这样：「用户注册时找不到验证码输入框」「结账流程有 5 步但只需要 2 步」。

## 2. UI：User Interface（用户界面）

UI 关心的是**界面本身呈现成什么样**，即用户直接看到、点到的那一层：

- **图形与文案**：图标、按钮形状、图片、界面上的文字措辞。
- **视觉设计**：颜色、像素级尺寸、阴影、间距、层级。
- **品牌 branding**：配色、字体、气质是否与品牌一致、是否可辨识。

UI 的问题长这样：「主按钮和背景对比度太低看不清」「两个图标风格完全不统一」。

## 3. 一句话对比

```text
UX  →  这个东西用起来「对不对、顺不顺」   （逻辑 / 可用性 / 研究）
UI  →  这个东西看起来「清不清楚、美不美」 （视觉 / 图形 / 品牌）
```

两者是**互补**而非对立：UX 决定「骨架和动线」，UI 决定「皮肉和表情」。UX 差会让用户放弃产品，UI 差会让用户不信任产品。

## 4. UI 的终极目标：让 App 更好用

这门课重点在 UI，而 UI 存在的意义不是「好看」，而是**让应用更好用**。它被拆成三个层层递进的子目标：

| 层级 | 目标 | 解决什么 | 对应知识板块 |
|---|---|---|---|
| 1 | **让用户不害怕** | 界面整洁、对齐、有一致性，用户敢上手 | 图形基础（对齐/网格/字体配色） |
| 2 | **让用户找到东西** | 重要内容被凸显，用户一眼看到重点 | 视觉层级（Visual Hierarchy） |
| 3 | **让用户会做事** | 元素看起来就能操作，用户知道能点 | 示能（Affordance） |

这三层是递进关系：一个**乱**的界面（第 1 层没过）谈不上层级，一个**层级混乱**的界面（第 2 层没过）用户根本找不到按钮，也就无法进入第 3 层。

```text
不害怕  →  找到东西  →  会做事
 图形      视觉层级      示能
```

## 5. 辨析练习：这是 UX 还是 UI 的工作？

| 任务 | 归属 | 理由 |
|---|---|---|
| 访谈 5 位用户，看他们能不能注册成功 | UX | 用户研究 + 可用性 |
| 把主按钮颜色改成品牌蓝并提高对比度 | UI | 视觉 / 品牌 |
| 重新设计结账流程，从 5 步减到 2 步 | UX | 逻辑性 / 效率 |
| 统一 App 内所有标题的字号和间距 | UI | 视觉一致性 |
| 决定「设置」入口放在导航的哪个位置 | UX | 信息架构 / 逻辑 |
| 给按钮加上投影，让它更像可点击的按钮 | UI | 视觉 + 示能 |

> ⚠️ 常见误区：把「好看」等同于 UI 的全部。UI 里还有**文案、示能、层级**这些非纯装饰的部分，它们同样决定好不好用。

## 6. 术语速查

| 英文 | 中文 | 备注 |
|---|---|---|
| User Experience (UX) | 用户体验 | 关注可用性与逻辑 |
| User Interface (UI) | 用户界面 | 关注视觉与图形呈现 |
| usability | 可用性 | UX 的核心度量维度之一 |
| user research | 用户研究 | 访谈、测试等方法的总称 |
| branding | 品牌 | UI 里保持一致性的重要来源 |

## ✅ 自查清单

- ✅ 能用自己的话说出 UX 与 UI 各关注什么（逻辑/可用性 vs 视觉/图形）？
- ✅ 知道 UX 不等于「体验好」，而落到**可用性、逻辑性、用户研究**？
- ✅ 记得 UI 的终极目标是「让 App 更好用」，并拆成**不害怕 → 找到东西 → 会做事**三层？
- ✅ 拿到一个任务能判断它属于 UX 还是 UI？
