用原生 JavaScript 构建界面时，你是在一步步指挥浏览器：先拿到节点、再改样式、再删一个元素。React 换了一套思路：你只描述「界面在某个状态下应该长什么样」，剩下的过程交给它。这篇讲清这个思维转变到底解决了什么问题。

## 1. 两种范式：指定「过程」vs 指定「结果」

| 范式 | 关注点 | 你要负责 | 谁负责细节 |
|---|---|---|---|
| 命令式 Imperative | **过程**（怎么做） | 每一步 DOM 操作 | 你自己 |
| 声明式 Declarative | **结果**（要什么样） | 只描述目标状态 | 框架（React） |

同一件事「把页面背景变绿」，两种写法：

```js
// 命令式：一步步告诉浏览器怎么做
document.body.style.backgroundColor = 'green'
```

```jsx
// 声明式：只描述「此状态下界面是这样」
return <body style={{ backgroundColor: 'green' }} />
```

命令式里，如果还要联动改文字颜色、移除某个提示条，你得**逐条补上**；声明式里，你只是重新描述「绿色背景 + 这个状态下该有的所有元素」，差异由 React 计算。

> 术语对照：Imperative（命令式）/ Declarative（声明式）/ state transition（状态转换）/ state machine（状态机）。

## 2. 为什么值得：状态转换会组合爆炸

界面本质是**状态机（state machine）**：每个「状态」是一套完整的界面，每次用户操作触发一次「转换」。

- 3 个状态 → 任意两两之间都可能跳转，共 **6** 种转换（`3 × 2`）
- 50 个页面 → 最少 **2450** 种转换（`50 × 49`）

命令式要求你**为每一种转换都写一段 DOM 操作代码**，转换数随状态数呈平方级增长：

| 状态数 | 需要手写的转换 |
|---|---|
| 3 | 6 |
| 10 | 90 |
| 50 | 2450 |

声明式只需要你**描述 50 个状态本身**，转换路径交给 React 去推导。状态数翻倍时，工作量只是线性增长 —— 这就是 React 的核心价值。

换个角度看命令式的痛：每多一个状态，你都要额外维护「进入它」和「离开它」的两组 DOM 操作。

```js
// 命令式：每个状态都要手写一组进出操作
function enterGreen() { document.body.style.background = 'green' }
function leaveGreen() { document.body.style.background = 'white' }
// 状态一多，这类函数数量随状态数平方级膨胀
```

而声明式里没有「进入/离开」，只有一句「这个状态下界面长这样」。

## 3. 团队协作下更容易失控

- 命令式：A 改了 `DOM`、B 又改了同一块，谁在什么时候动了哪个节点**无从追踪**。
- 未跟踪的 DOM 变更会成为隐藏 Bug 的温床 —— 界面最终长什么样，取决于所有改动代码的执行顺序。
- 声明式：界面由「状态 → 视图」的纯映射决定，任何人改的都是**输入**，输出可预测、可复现。

## 4. 命令式的适用边界

命令式并非一无是处：**很简单的场景**（切个 class、改个颜色）它又快又直接，不值得上框架。

但一旦 **DOM 之外还存在数据**（如从服务端拿到的数组），麻烦就来了：

- 你要同时维护**两个状态机** —— JS 里的数据和真实 DOM 各一份。
- 每次数据变，都得手动把 DOM 同步成一致；遗漏一处就出现「数据和界面不一致」。
- 这种需要处理的边界情况**无穷无尽**，正是 React 想消灭的。

> ⚠️ 常见误区：以为「声明式 = 代码更少」。恰恰相反，声明式代码**通常更多**，但它把「组合爆炸的转换」换成了「可预测的状态描述」，**扩展性**才是它胜出的地方。

## 5. 一个澄清：这里的「生命周期」其实不是 class 生命周期

本模块来源讲座标题叫 **Lifecycle（生命周期）**，容易让人联想到旧版 class 组件的 `componentDidMount` 那套钩子。但它的实际内容是 **「How React Works」**：命令式/声明式、虚拟 DOM、state 与渲染循环。

本项目采用**函数组件 + Hooks** 范式，**不涉及** class 生命周期方法，看到「Lifecycle」请按「React 如何工作」理解。

## 6. 一句话总结

命令式让**你**维护「从 A 到 B 怎么改」的每一步；声明式让你只回答「B 长什么样」，把「怎么改」外包给框架。选择声明式不是因为代码更短，而是因为它把**组合爆炸**关进了框架内部。
