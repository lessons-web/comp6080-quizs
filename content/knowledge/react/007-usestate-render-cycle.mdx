没有状态的组件只是「一次性」的静态模板。`useState` 让函数组件拥有了**随交互变化的数据**，并驱动界面自动重渲染。理解它的关键在于记住一条闭环：**渲染 → 改 state → 再渲染**。

## 1. 语法：`const [count, setCount] = useState(0)`

`useState` 是 React 的 **Hook**。它返回一个**数组**，用**数组解构**拿到两样东西：

```jsx
const [count, setCount] = useState(0)
```

| 位置 | 名称 | 含义 |
|---|---|---|
| 第一个 | `count` | **当前状态值**（也叫 state 变量）。 |
| 第二个 | `setCount` | **更新函数（setter）**，用来改变这个状态。 |
| 参数 | `0` | **初始值**，只在首次渲染时使用。 |

约定俗成：setter 命名用 `set` + 首字母大写的状态名（`count` → `setCount`）。

> 术语对照：state（状态）/ hook（钩子）/ useState / re-render（重新渲染）/ asynchronous update（异步更新）/ conditional rendering（条件渲染）。

## 2. 触发更新：改 state → 重新渲染

调用 setter 只是「**请求**」React 更新状态。React 会把状态更新安排成**异步**处理：

```jsx
function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      点了 {count} 次
    </button>
  )
}
```

流程：

1. 点击 → 执行 `setCount(count + 1)`，发出**异步状态更新**。
2. React 处理更新，把 `count` 变成新值。
3. 更新完成后，**重新执行这个组件的 render**（函数组件就是**再调用一次函数**），此时拿到的 `count` 是新值。
4. 新一版界面按 React 的虚拟 DOM / Diff 机制落到屏幕上。

> 关键点：**setState 不是同步的**。调用 setter 之后，当前这一轮执行的 `count` 仍是旧值，别指望下一行就能读到新值。

## 3. render 的返回值 = 你要求屏幕呈现的内容

函数组件的 `render`（即函数体返回的 JSX）就是**「你要求 React 在这个状态下呈现到屏幕上的内容」**：

- 它是**纯粹由 state / props 推导出的「界面描述」**。
- 状态一变，React 就再执行一次 render，拿到**新的界面描述**，再算差异更新屏幕。
- 你**从不手动改 DOM** —— 只负责「按当前 state 描述界面」。

```jsx
// render 是对「当前 state 应呈现什么」的声明
function Profile({ name }) {
  const [expanded, setExpanded] = useState(false)
  return (
    <div>
      <h2>{name}</h2>
      <button onClick={() => setExpanded(!expanded)}>
        {expanded ? '收起' : '展开'}
      </button>
      {expanded && <p>详细资料…</p>}
    </div>
  )
}
```

## 4. 完整闭环：render → 改 state → 再 render

```text
① render
   函数组件被调用，读取当前 state，返回界面描述
        │
        ▼
② 用户交互
   onClick 等事件触发 → 调用 setter（异步请求更新）
        │
        ▼
③ React 处理更新
   状态变为新值 → 重新执行 render（携带新值）
        │
        └────────► 回到 ①（新的界面描述 → Diff → 更新屏幕）
```

这是一个**闭环（loop）**：每次状态变化都会走一圈，直到不再有新的更新。

## 5. 条件渲染：`&&` 与三元

render 里可用 JS 逻辑决定「某块界面渲染不渲染」：

```jsx
// 只有 dropdownVisible 为 true 时才渲染这个列表
{dropdownVisible && (
  <ul>
    <li>选项 A</li>
    <li>选项 B</li>
  </ul>
)}

// 二选一用三元
{isLoading ? <Spinner /> : <Content />}
```

`dropdownVisible && <ul>…</ul>` 的含义：`false && …` 直接得到 `false`，React 会**什么都不渲染**；为 `true` 时才返回那个 `<ul>`。

> 注意：`0` 与 `''` 是假值但会被 React 渲染出来，`&&` 左侧若可能是数字/字符串，最好显式写比较（如 `count > 0 && …`）。

## 6. 常见反模式（❌ 别这么写）

```jsx
// ❌ 直接改 state 变量：界面不会更新
count = count + 1

// ❌ 以为 setState 是同步的
setCount(count + 1)
console.log(count)   // 这里仍是旧值！

// ❌ 在 render 过程中调用 setter，可能造成无限循环
function C() {
  const [n, setN] = useState(0)
  setN(n + 1)        // 每次渲染都触发更新 → 死循环
  return <p>{n}</p>
}
```

> 想「基于上一个状态」更新时，推荐**函数式更新**：`setCount((prev) => prev + 1)`，避免一次事件里多次调用时读到过期值。

## 7. 澄清：本项目用 Hooks，不用 class

`useState` 属于**函数组件 + Hooks** 范式。本项目（React 19）一律使用它，**不引入** class 组件的 `this.state` / `setState` / `componentDidMount` 那套写法。

## 8. 自查清单

- ✅ 能正确写出 `const [x, setX] = useState(初始值)` 并说清三个部分。
- ✅ 明确 **setter 是异步的**，调用后本行读不到新值。
- ✅ 能复述闭环：render → 改 state → 再 render。
- ✅ 理解「render 的返回值 = 要求屏幕呈现的内容」。
- ✅ 会用 `&&` / 三元做条件渲染，并注意 `0` / `''` 的假值陷阱。
- ✅ 知道**必须用 setter 改状态**，不能直接给 state 变量赋值。
